# 0006 依赖审计报告

- 状态：已采纳
- 日期：2026-10-03
- 来源：DevHub ADR 0012

## 背景

质量检查通过并不代表依赖没有已知漏洞。部分开发工具链告警在上游可能长期没有修复。renderer 库放在 devDependencies，仅审计生产依赖会漏掉随 UI 打包的库。

## 决策

- CI 有独立的 Ubuntu 审计任务（`scripts/dependency-audit.mjs`），对全部依赖执行 `pnpm audit --json`，在 job summary 中列出严重性、GHSA 与依赖路径，并上传原始响应。
- 报告模式：漏洞告警不阻断功能检查和打包；不忽略或豁免任何 GHSA。网络错误、超时、无效响应仍使任务失败，避免误报为审计通过。
- 不自动运行 audit fix，不覆盖到尚未发布或未经上游确认的版本；依赖更新由 dependabot 发起。
- 已知告警记录在进度文档；修复发布后先更新并验证，再评估是否启用 high / critical 阻断门槛。

## 备选与理由

- 立即以所有 high 告警阻断：无可用修复时会长期阻断与漏洞无关的开发。
- 忽略已知 GHSA 或只审计生产依赖：会隐藏告警，且遗漏 renderer 依赖。
